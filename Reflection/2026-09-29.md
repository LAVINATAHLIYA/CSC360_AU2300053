## What I Understood

### Master-Detail Implementation (Deeper Look)

- Selecting an item in the master section triggers an event that passes the selected item's data to the detail section
- The detail section then updates its UI components to display the full information of that item
- This connection between master and detail is what makes the pattern powerful — the two sections always stay in sync

### `MainApp` and `MasterDetailApp` Responsibilities

- `MainApp` → starts the JavaFX runtime and loads the initial scene
- `MasterDetailApp` → owns the overall layout, creates the master and detail panels, and manages how they talk to each other
- Understanding which class owns which responsibility makes the codebase much easier to navigate

### Event Handling — The Core of Interactive JavaFX Apps

- Every user interaction (clicking, selecting, typing) generates an event
- Event handlers are registered to listen for specific events on specific components
- When the event fires, the handler method runs and updates the UI
- Without event handling, the application would be completely static — no reaction to the user

### Method Overriding and `@Override`

- When a subclass provides its own version of a method from its parent class, that is **method overriding**
- The `@Override` annotation signals this intention clearly and lets the compiler catch mistakes
- If the method signature doesn't match the parent, the compiler immediately shows an error — this is very helpful

### Code Organization with Packages

- Packages in Java group related classes — similar to folders organizing files
- Separating UI code, business logic, and data models into different packages keeps things clean
- It also makes it easier for team members to work on different parts without stepping on each other
