## What I Understood

### TableView vs ListView

- `ListView` → shows a simple scrollable list, good for displaying one value per item
- `TableView<T>` → shows data in rows and columns, better when each item has multiple fields to display
- For the Master-Detail project, `ListView` or `TableView` in the master section depends on how much info we want visible at a glance
- `TableView` supports sortable, resizable columns which is more powerful for complex data

### CSS Styling in JavaFX

- JavaFX supports CSS styling through `.css` files linked to the scene
- You can change fonts, colors, padding, borders, backgrounds, hover effects, etc.
- Using a stylesheet keeps all visual styling in one place, separate from Java logic
- CSS class selectors like `.list-view`, `.table-row-cell` are built-in JavaFX CSS classes

### Thread Safety in JavaFX

- JavaFX is **single-threaded for UI** — only the JavaFX Application Thread can update UI components
- If you update a label or list from a background thread, you get a runtime exception
- The fix is to wrap the UI update inside `Platform.runLater(() -> { ... })` — this schedules the update to run on the correct thread
- This becomes important when loading data from a database or network in the background
