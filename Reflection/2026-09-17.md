## What I Understood

### The Master-Detail Design Pattern

- The application is split into two connected sections:
  - **Master section** → shows a list or collection of items
  - **Detail section** → shows the full information of whichever item is currently selected
- When you click an item in the master list, the detail section updates automatically
- This pattern makes it easy to browse many items without cluttering the screen

### Application Structure

- `MainApp` → entry point, launches the JavaFX application
- `MasterDetailApp` → manages the main layout and coordinates the two sections
- Different packages separate different responsibilities (UI, model, logic)
- Keeping classes small and focused makes the code easier to read and change

### JavaFX Components

- The UI is built from JavaFX components — layouts, list views, labels, text fields, etc.
- Different UI elements interact through **event handling**
- When a user selects an item in the list, an event fires and the detail view responds to it

### Event Handling in JavaFX

- User actions (click, select, type) generate **events**
- Event handlers are attached to components to define what should happen when an event fires
- The master list's selection listener calls a method that updates the detail panel
- This chain — **user action → event → handler → UI update** — is the core of event-driven programming

### OOP Concepts in Practice

- `@Override` annotation is used when a subclass provides its own implementation of an inherited method
- Inheritance allows classes to share common behavior while customizing specific parts
- Packages group related classes together, keeping the project organized and navigable
