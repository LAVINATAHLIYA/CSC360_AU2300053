## What I Understood

### Generic Programming

- Generics let you write a class or method once and use it with any type
- Example: `MasterDetailController<T>` can work with students, books, products — anything
- The compiler enforces type safety so you can't accidentally mix types
- Raw types (without generics) are discouraged because they lose this safety

### Java Collections — `List` vs `ObservableList` vs `Map`

- `List<T>` → ordered collection, accessed by index
- `ObservableList<T>` → a JavaFX-aware list that automatically notifies the UI when items change — used directly in `ListView`
- `Map<K, V>` → stores key-value pairs, useful for fast lookups by ID or name
- Choosing the right collection type affects both correctness and performance

### Filtering and Searching

- With a small dataset, a simple linear search through a list is fine
- With millions of records, we need smarter approaches:
  - **Indexed search** — pre-build an index on searchable fields
  - **Sorted data + binary search** — much faster than scanning everything
  - **Lazy loading** — only load items the user is likely to need right now
- The choice of algorithm has a huge real-world impact when data is large

### Caching Strategies

- Keeping everything in memory is impossible when the dataset is very large
- A **cache** holds the most recently or most frequently needed items
- When the user searches, we first check the cache; if the item isn't there, we fetch from the database
- **Cache eviction** — deciding which items to remove when the cache is full (LRU is a common strategy)
- Predicting what the user is likely to search for next makes caching smarter
