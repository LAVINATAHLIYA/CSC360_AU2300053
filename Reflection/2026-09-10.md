## What I Understood

### Streaming vs Downloading

- Streaming sends data in small pieces so you can start using it before the whole file arrives
- Downloading transfers the complete file to your device before you use it
- Streaming is great for live content, videos, cloud games, and remote desktops
- Downloading is better when you need a file repeatedly because the saved copy avoids re-fetching data
- Data usage depends on video quality, compression, and how much content you actually watch
- Streaming uses a **buffer** — if internet slows down and the buffer empties, you get the **buffering pause**
- Adaptive bitrate streaming adjusts quality based on your current network speed

### Where Streaming is Used in Graphics

- **Video Streaming** — video is split into small segments, compressed, and sent to the player as needed
- **Texture and Model Streaming in Games** — games load only the assets needed right now, unloading others to save memory
- **Cloud Gaming** — the game runs on a remote server, the server renders the frames, and those frames are streamed as video to your screen (e.g., NVIDIA GeForce NOW)
- **Remote Desktop** — screen output is captured, compressed, and streamed to another device
- **VR/AR** — requires very low latency streaming; techniques like foveated rendering and prediction help reduce delay
- **Progressive Image Loading** — large images load in low quality first, then improve gradually

### Server-Side Rendering (SSR) vs Client-Side Rendering (CSR)

| Feature | SSR | CSR |
|---|---|---|
| HTML is generated | On the server | In the browser |
| First load speed | Content appears faster | May be slower due to large JS files |
| SEO | Generally easier | Needs extra support |
| Interactivity | Available after hydration | Available after JS loads |

- SSR is better for public, content-heavy websites
- CSR is better for dashboards and interactive apps that run behind a login
- Modern frameworks often mix both approaches

### Storing Images and Image Metadata

- Store the **actual image file** in object storage (like Amazon S3)
- Store the **image information** in a database (image ID, URL, dimensions, owner, upload time, etc.)
- This separation makes it easier to query metadata without loading the full image file

### Platform Abstraction in AWT

- AWT provides a cross-platform API so the same Java code can work on Windows, macOS, and Linux
- Under the hood, AWT delegates to the native platform's UI toolkit
